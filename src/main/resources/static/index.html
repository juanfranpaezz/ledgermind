LedgerMind · auditor demo

Payments core with a double-entry ledger, idempotency and post-quantum auditing via MCP.

⚖️ DEMO with simulated money. The ledger is tamper-evident (append-only + hash/signature), not a production fraud-prevention system. What is real and defensible is the concurrency and idempotency design underneath.  ·  Code

1 · Idempotency: a retry does not charge twice

I make the same transfer twice with the same idempotencyKey. It must create a single posting and move the money only once.

—

2 · Tamper-evidence: editing the ledger breaks the chain

I simulate an attacker with database access who edits a posting by direct SQL. The ML-DSA signature stays valid (it signed the original head), but the hash-chain no longer recomputes: proof that it was altered after signing.

—

3 · The auditor answers: was the ledger tampered with?

This is the same report the MCP tool verify_journal_integrity returns to an AI agent. The agent reads and explains; it can never move a single peso.

—

4 · Reconciliation: the matcher classifies the discrepancies with the PSP

I match the ledger against a (simulated) PSP settlement feed. The matching is 100% deterministic Java: an unposted fee, a PSP charge without a posting, a posting the PSP does not report. This is the same structured result the MCP tool explain_reconciliation_discrepancy gives an agent to narrate and prioritize (no AI runs here; the code decides, the AI would only explain).
